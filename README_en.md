# vsc_stm32_template

[Latviski](README.md)

A VS Code + CMake starting point for the **STM32F103C8T6 "Blue Pill"**.
It's set up with STM32CubeMX and ST's official VS Code extension, and you flash and debug it with an **ST-Link V2** (a clone is fine).

| Setting      | Value                                                  |
|--------------|--------------------------------------------------------|
| MCU          | STM32F103C8Tx (LQFP48, 64 KB flash, 20 KB RAM)         |
| Clock        | 8 MHz HSE crystal × PLL 9 = **72 MHz** (APB1 36, APB2 72, USB 48) |
| Debug        | SWD (PA13 SWDIO, PA14 SWCLK)                           |
| Build        | CMake + Ninja + arm-none-eabi-gcc (ST extension bundles) |
| HAL          | STM32Cube FW_F1 V1.8.x, only the files you use are copied |
| Demo         | PC13 LED (`LEDBUILTIN`, active-low) blinks at 1 Hz     |

## Layout

```
App/              <- YOUR code. CubeMX never touches this folder.
  Inc/app.h
  Src/app.c       App_Init() + App_Loop() + App_Error()
  Inc/taimeris.h  software timers (Timer_t, CheckTimer, ...)
  Src/taimeris.c
Core/             <- generated by CubeMX (main.c, HAL config, interrupts)
Drivers/          <- generated: HAL + CMSIS (committed, so a clone builds immediately)
cmake/            <- generated: toolchain file + CubeMX source list
CMakeLists.txt    <- generated once, then yours (App/ is added there)
CMakePresets.json <- Debug / Release presets
*.ioc             <- open this in CubeMX to change pins and peripherals
```

Rule: in `Core/` you only edit between `/* USER CODE BEGIN */ ... /* USER CODE END */` markers.
Everything else goes in `App/`. New modules go there as `App/Inc/<name>.h` + `App/Src/<name>.c`;
add each `.c` file to `target_sources` in `CMakeLists.txt`.

Main loop pattern (see `App/Src/app.c`): one `Timer_t` per periodic job, then
`if (CheckTimer(&TIMER, currentTime))` in `App_Loop()`.

If startup fails (for example, the crystal doesn't start), `Error_Handler()` calls `App_Error()`,
which blinks PC13 fast (~5 Hz) forever.

Formatting: tabs + CRLF, set by `.editorconfig` and `.vscode/settings.json`.

## One-time PC setup (Windows)

1. **VS Code** with the **STM32Cube for Visual Studio Code** extension
   (`stmicroelectronics.stm32-vscode-extension`; VS Code suggests it when you open this folder).
2. **Toolchain**: on first open, the ST extension downloads its own bundles (GCC, CMake, Ninja, ST-Link tools)
   into `%LOCALAPPDATA%\stm32cube\bundles`. Accept its prompts. Installing STM32CubeCLT separately is optional.
3. **STM32CubeMX** (6.17 or newer), only needed when you change the `.ioc`.
4. **ST-Link USB driver** (STSW-LINK009).
5. **EditorConfig** extension (suggested automatically), so new files get tabs + CRLF.

## Wiring the ST-Link V2

| ST-Link | Blue Pill (4-pin header at the end) |
|---------|------------------------------|
| 3.3V    | 3.3                          |
| SWDIO   | DIO (PA13)                   |
| SWCLK   | CLK (PA14)                   |
| GND     | GND                          |

Leave both yellow jumpers (BOOT0 and BOOT1) at **0**.

## Daily workflow (VS Code only)

| Action | How |
|---|---|
| Build | `F7` or *Build* in the status bar |
| Build + flash + debug (stops at `main`) | `F5` |
| Build + flash + run, no debugger | `Ctrl+F5` |
| Change pins/peripherals | open the `.ioc` in CubeMX → **Generate Code**, then `F7` |

The debug config is `.vscode/launch.json` ("Blue Pill: build + flash + debug").
If you've been using CubeIDE, these map as follows: Debug ≈ `F5`, Run ≈ `Ctrl+F5`, and the CubeProgrammer step happens automatically.

**BOOT0 must be 0** (both yellow jumpers at 0). With BOOT0 = 1 the chip starts the built-in serial bootloader,
so your program never runs, even though flashing over SWD still succeeds.

## Starting a new project from this template

1. Copy the folder (or use "Use this template" on GitHub).
2. Rename `vsc_stm32_template.ioc` to `<name>.ioc`, open it in CubeMX, set
   *Project Manager → Project Name* to `<name>`, and click **Generate Code**.
3. In `CMakeLists.txt`, set `CMAKE_PROJECT_NAME` to `<name>` (if CubeMX didn't).

## Troubleshooting

- **Clone chip (CKS32 / CS32 / APM32 / GD32)**: these mostly work with the ST-Link V2.
  If ST's GDB server refuses the chip ("not an STM32 device" or a wrong IDCODE),
  use OpenOCD with `-c "set CPUTAPID 0"` and the Cortex-Debug extension instead.
- **"No target found" after flashing an old project with SWD disabled**: hold RESET, start the flash,
  release RESET about 0.5 s later. Or set the BOOT0 jumper to 1, power cycle, flash, then set BOOT0 back to 0.
  (This template keeps SWD on: *SYS → Debug = Serial Wire*. Never set it to "No Debug".)
- **The LED looks inverted**: PC13 is active-low. `GPIO_PIN_RESET` turns it **on**.
- **PC13 blinks fast**: something during startup called `Error_Handler()`. Most often the crystal didn't start:
  in CubeMX, switch the PLL source to HSI/2 × 16 = 64 MHz.
